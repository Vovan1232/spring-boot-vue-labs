# Читальня · Лабораторна робота № 7

Окремий застосунок Spring Boot 3 із реєстрацією, автентифікацією, рольовим доступом і обмеженням активних сесій. Інтерфейс створено на Thymeleaf. Hibernate зберігає користувачів і ролі у вбудованій файловій H2.

## Запуск

Потрібні Java 17+ та Maven. Відкрийте термінал у папці з `pom.xml` і виконайте:

```sh
mvn spring-boot:run "-Dspring-boot.run.profiles=demo"
```

Відкрийте [головну сторінку](http://127.0.0.1:8087/). Профіль `demo` створює три навчальні акаунти в окремій базі H2. Пароль для всіх демоакаунтів — `DemoLab7!`.

| Логін | Роль | Сторінки після входу |
| --- | --- | --- |
| `demo_user` | USER | `/user` |
| `demo_manager` | MANAGER | `/user`, `/manager` |
| `demo_admin` | ADMIN | `/user`, `/admin` |

Щоб запустити застосунок без демоакаунтів, виконайте `mvn spring-boot:run`. Новим користувачам, створеним через `/registration`, призначається тільки `ROLE_USER`. H2 зберігається у папці `data`. Застосунок слухає тільки `127.0.0.1`.

## Як перевірити

1. Зареєструйте акаунт і увійдіть. Відкрийте `/user`, потім `/admin`. Перший маршрут доступний, другий повертає **HTTP 403**.
2. У демопрофілі увійдіть під `demo_manager` і перевірте `/manager`. Увійдіть під `demo_admin` і перевірте `/admin`. Адміністратор не має доступу до `/manager`, а менеджер — до `/admin`.
3. У двох браузерах або окремих профілях увійдіть під одним логіном. Після другого входу оновіть `/user` у першому браузері. Застосунок перенаправить на `/login?expired`. У другому браузері кабінет залишається доступним.
4. Натисніть «Вийти». Застосунок поверне на головну сторінку, а наступний запит до кабінету вимагатиме входу.

## Реалізація

- `User` та `Role` пов’язані через `@ManyToMany` і таблицю `user_roles`. Логіни унікальні й нормалізуються до нижнього регістру.
- `UserService` реалізує `UserDetailsService`, завантажує ролі та хешує паролі через `BCryptPasswordEncoder`.
- `SecurityConfig` налаштовує власну форму входу, рольові маршрути й завершення сесії. Запити на реєстрацію, вхід та вихід захищені CSRF-токеном.
- `SessionRegistryImpl` зберігає активні сесії в пам’яті застосунку. `HttpSessionEventPublisher` повідомляє реєстр про завершення сесій. Ліміт в одну сесію діє в межах одного екземпляра застосунку.
